# Documentation content — agent guide

Starlight content collection for `/docs/`. Pages live under `docs/` (the
directory name is the route prefix); `404.md` sits at the collection root.

Read `DOCS_ARCHITECTURE.md` in the website root for the information
architecture and the source-of-truth order. This file is the working guide.

## File conventions

- `.mdoc` (Markdoc) for every docs page — never `.md`; `404.md` is the one
  exception Starlight expects.
- Frontmatter: `title` required, `description` required for SEO.
- The sidebar is autogenerated from the directory tree (`astro.config.mjs`).
  Adding a page means adding a file in the right section folder; there is no
  sidebar list to edit.
- The URL is the path under `src/content/docs/`:
  `docs/language/queries.mdoc` → `/docs/language/queries/`.
- Files starting with `_` are ignored by the content loader. This guide lives
  one level up (`src/content/AGENTS.md`) because an `AGENTS.md` inside `docs/`
  would be published as a page.

## Executable docs contract

- Every complete QQL snippet goes in a `{% qqlExample title="…" %}` block.
  `pnpm validate:qql` extracts each one and parses it with a freshly built
  Node-target WASM SDK. Raw ```qql / ```sql fences fail the check.
- `{% qqlExample %}` also renders a "Try in playground" link carrying the exact
  query, so the docs and the playground cannot disagree.
- Only `qqlExample` bodies are verified; inline `code` spans are prose.
- Available tags (`markdoc.config.mjs`): `qqlExample`, `terminal`,
  `glassCard`, `apiField`, `techBadge`, `grid`, `faqList`, plus Starlight's own.
  Do not simulate these with ad-hoc HTML.

## Content rules

- Fixtures + grammar + parser outrank prose. Fix the prose or the
  implementation contract — never invent a documentation-only dialect.
- Keep isolation (`WHERE`, `inject_filter`) separate from physical routing
  (`SHARD` / shard keys).
- Keep execution claims transport-neutral unless REST / gRPC / edge
  differences are the point of the page.
- Do not duplicate fixture source or invent changelog entries; link GitHub
  Releases.
- Error codes named in prose must exist in the runtime's error table and the
  error-code reference page.

## Verify

1. `pnpm validate:qql` — every example parses (also part of `pnpm check`).
2. `pnpm check` — includes `check-site-anchors.mjs` (dead `/docs/...` links and
   `#fragment`s that do not exist on the target page fail) and
   `check-headers.mjs` (CSP rules for every route).
3. `pnpm dev` and read the page: code blocks use the QQL TextMate grammar,
   `qqlExample` captions render, and "Try in playground" opens the query.
